# 像人的细节

这份文档讲的是：一个 LLM 机器人为什么看起来像在「聊天」，而不是像在「应答」。

人格词决定她说什么，这里讲的是**什么时候说、说几条、什么时候闭嘴**。
后者比前者更难，也更容易被忽略。下面每一条都对应 `aemeath.py` 里的实际实现。

---

## 一、发声节奏：别当复读机

最毁气氛的不是说错话，是**秒回**。真人不会在你打字打到一半时抢答。

```python
_DEBOUNCE_SEC = 6.0   # 他停手多久之后才开始回
_DEBOUNCE_MAX = 20.0  # 一直不停手，最多攒这么久
```

- 每收到一条消息，`_enqueue()` 重置 6 秒计时器。
- 如果对方连续发消息，计时器一直被推后——但 `_DEBOUNCE_MAX` 兜底，
  攒够 20 秒就必须回，否则话多的用户永远等不到回应。
- 攒下来的几条会被 `_process_batch()` 合成**一轮**处理：文字按顺序拼接，
  多张图只取第一张给模型。所以对方连发五条，得到的是一个连贯的回答，
  而不是五次各说各的。

回复本身也要像手打出来的：

- `split_bubbles()` **不按句号硬切，只认她自己打的换行**。
  模型没法真的"发两条消息"，所以让它用换行表达分条意图：
  她写了三行，就发三个气泡。这是整个项目里最省事也最准的一条约定。
- 不到 5 个字的碎片（「哟。」「嗯。」）并回上一条——那是起头，不是独立一条。
  但「外行……行吧。」有七个字，那是一个完整的拍子，要单独发。
- 单行超过 90 字，才在这一行内部按句末标点切开（`_cut_sentences`，默认 60 字一段），
  避免一条消息 300 字糊满屏幕。
- 超过 4 条会合并；群聊里超过 3 条也合并——连发五六个气泡就成了刷屏。
- 气泡之间插入 `random.uniform(0.7, 2.0)` 秒的随机间隔（发图间隔 0.5–1.2 秒）。
  **必须随机**：固定 1 秒的间隔比秒回更像机器人。

`deliver()` 里还有一道防线：

```python
text = re.sub(r"(?<!\d)0\d{3}(?!\d)", "", text)
```

图库编号是内部 id，人格词里已经严禁外露，但提示词挡不住的时候，
由这行把漏出来的四位编号抹掉。**提示词负责意图，代码负责兜底**——
这个分工在后面每一层都会重复出现。

**为什么这样做**：IM 里的「一条消息」是有物理长度的。
LLM 天生爱写整段，切成气泡是把它拉回聊天尺度最有效的一步。

## 二、时间感：她得知道现在几点

模型没有时钟。不给时间，它会在凌晨三点说「今天天气不错」。

`time_note()` 拼出这样一段：

```
[系统时间] 快十一点了。上次说话是三天前。
```

- `clock_phrase()` 给模糊钟点（「快十一点」而不是「22:47」）——人不会精确报时。
- `part_of_day()` 给时段（凌晨 / 上午 / 下午 / 深夜）。
- `humanize_gap()` 把时间差说成人话：刚才 / 半小时前 / 几天前。

**关键工程点**：这些信息全部附加在**最后一条 user 消息**上，
绝对不放进 system prompt。

因为 `build_static()` 返回的 system 前缀（人格 + 记忆摘要）如果掺了时间，
每轮都会变——DeepSeek 的 prompt cache 就永远命中不了，成本翻几倍。
把变化的部分赶到末尾，前缀稳定，缓存才生效。

这是个在「像人」和「省钱」之间必须同时满足的约束，处理不好只能二选一。

## 三、记忆分层：她会记得，也会忘

不分层的话只有两种结局：要么忘了昨天，要么上下文爆掉。

`memory.json` 里每个会话存两部分：`summary`（一段压缩后的记忆）+ `msgs`（最近原始对话）。

三层压缩，逐层收紧：

| 函数 | 触发 | 做什么 |
|---|---|---|
| `summarize()` | 原始消息攒够一批 | 旧对话 → 一段新记忆，然后删掉旧对话 |
| `condense_summary()` | 摘要超过 1200 字 | 把摘要本身再压一遍，给它一个天花板 |
| `maintain_memory()` | 定期 | 收尾、清理、保证结构完整 |

`build_static()` 把 `summary` 注入 system：

```
【你还记得的事】
（或：这是你们第一次说话，之前没有记忆）
```

**为什么"第一次说话"要单独写一句**：空字符串会让模型以为自己失忆了，
然后开始编造「我们之前聊过」。显式告诉它"没有记忆"，
它才会按初见的语气说话。

记忆规则 `MEM_RULES` 还会提醒：记忆是摘要，不是逐字记录，
不要声称"你说的每句话我都记得一字不差"。

## 四、不打扰：这是最像人的一层

主动发消息是双刃剑。发得好是"她想起你了"，发得差是"骚扰"。

```python
PRO_GAP_SEC         = 4 * 3600   # 安静满四小时才可能开口
PRO_COOLDOWN_SEC    = 2 * 3600   # 两次主动之间至少两小时
PRO_UNANSWERED_WAIT = 12 * 3600  # 上次主动没得到回应，隔这么久才允许再说
PRO_DAY_MAX         = 2          # 一天最多主动两次
PRO_QUIET           = (1, 8)     # 凌晨一点到早八点绝不发
PRO_TICK            = 300        # 每五分钟检查一次
```

五道闸门同时满足才会开口。任何一道不满足就安静待着。

其中最有用的两条：

- **`PRO_UNANSWERED_WAIT`**：她主动说了话，你没回，那就等 12 小时。
  真人不会连发三条"在吗"。这一条基本消灭了"黏人感"。
- **`PRO_QUIET`**：凌晨一点到早八点不发。半夜的手机震动是不可原谅的。

群聊是另一套规则。`_mentioned_me()` 判断有没有 @ 她：

- 被 @ 到 → 回，并在群里保持 `GROUP_ACTIVE_SEC = 300` 秒的活跃窗口
  （接下来五分钟内的消息会进入上下文，方便接话）。
- 没被 @ 到 → 只记录，不说话。群上下文只留最近 `GROUP_KEEP = 24` 条。

**核心判断**：群里沉默是礼貌，私聊沉默是冷淡。同一套阈值不能两处通用。

## 五、不过期：不补不回，不重复

```python
_STALE_SEC = 600   # 超过 10 分钟的消息不再回
```

三道筛查，都在 `on_message()` 里、派活之前完成：

1. `_mark_seen()` — 飞书的事件投递是「至少一次」，处理慢了服务端会重推
   （实测间隔约 5 分钟）。不按 message_id 去重，她就会对同一句话回两遍。
   去重表 `_seen.json` 滚动保留 `_SEEN_MAX = 500` 条。
2. `_sent_before_start()` — 她下线期间你发的消息，启动后**不补不回**。
   一开机就收到五条陈年回复，是最典型的机器人感。
3. `_too_old()` — 超过 10 分钟的旧消息直接丢。

还有 `_acquire_single_instance()`：只允许跑一个实例。
两个进程同时连 WebSocket，同一条消息会回两遍，日志也会互相覆盖。

**为什么"不补"是对的**：人不会在你三小时前说的话下面接着回。
错过就是错过了。这个"错过"本身反而是真实感的一部分。

## 六、洗模型味：四道后处理

模型的原始输出带一堆它自己意识不到的痕迹。`deliver()` 之前过四遍：

| 函数 | 洗掉什么 |
|---|---|
| `strip_paren_actions()` | `（笑）` `（沉默）` `（歪头）` 这类括号动作。IM 里没人这么打字。 |
| `strip_tool_calls()` | 模型偶尔不真调工具，而是把调用**写成文本**吐出来。这种残渣绝不能发出去。 |
| `clean_markdown()` | 飞书不渲染 Markdown。`**加粗**`、`##` 会原样显示成符号。 |
| `split_bubbles()` | 最后切成气泡。 |

`strip_paren_actions()` 的规则是：短括号（「（笑）」）整条丢掉；
长括号说明是句正话，只把外层括号剥掉。

它还有个兜底：一整行都被括号包住时不算旁白，而是**先只删括号本身、把正文留住**。
这一条是踩出来的——原来只要括号在行的两端就会被当成整段旁白，
于是「（笑）好啊（歪头）」被剥成空字符串，那条回复直接成了空白。
**模型输出的边界情况，永远是靠真实对话日志发现的，不是靠想象。**

## 七、图片：让它稀缺

```python
LIB_MAX_ITEMS = 60      # 库存上限，满了删最旧的
LIB_MAX_HINT  = 20      # 一次最多给她看 20 条候选
PIC_GAP_SEC   = 40 * 60 # 两次发图至少隔 40 分钟
PIC_DAY_MAX   = 6       # 一天最多发 6 张
```

流程是：她决定发图时输出 `[图:0037]`，`split_images()` 摘出编号，
`send_image()` 走飞书两步接口（先换 image_key，再发 image 消息）。

`build_pic_hint()` 把候选清单塞进上下文：

```
[可发图库] 编号 这些图，各「适合什么时候发」：0001 他夸你的时候 | 0037 深夜
```

三条设计原则：

1. **编号不外露**。人格词里明确要求：跟他说话只能说"那张"，编号是系统和她的私事。
2. **宁可不发**。人格词写了"拿不准就不发，发错一张比不发难受得多"。
3. **物理节流**。40 分钟 / 6 张是硬闸门，不靠模型自觉。

**为什么强调稀缺**：图是稀缺资源才显得珍贵。随时能发图的机器人，
发图这件事本身就贬值了。

---

## 小结

这六层里，没有一层是"让 AI 更聪明"。它们全都在做同一件事：

> **给模型加上它天生没有的约束——延迟、遗忘、沉默、稀缺。**

拟人的本质不是能力更强，而是**行为有边界**。
真人说话会停顿、会忘、会懒得回、会舍不得发那张图。
把这些"缺陷"工程化，比在提示词里写一百遍"你要像真人"有效得多。
